# Universal Web Methodology

1. **Discovery:** understand business, audience, offer, goals, constraints, budget and timeline.
2. **Research:** study competitors, audience language and relevant references; separate evidence from assumptions.
3. **Strategy:** define value proposition, primary message, user action and success indicators.
4. **Information architecture:** define pages, navigation, hierarchy and user journey.
5. **UX and content:** plan tasks, forms, states, accessibility and verifiable copy.
6. **Creative direction:** define concept, typography, color, grid, imagery, components and responsive behavior.
7. **Experience design:** plan useful interactions and motion where they support comprehension, identity or task completion.
8. **Technical architecture:** choose stack and integrations proportionate to complexity, cost and maintenance.
9. **Implementation:** build incrementally with semantic structure, coherent components and justified dependencies.
10. **QA:** test flows, links, forms, responsive behavior, accessibility, SEO, security and performance.
11. **Delivery:** publish only with authorization; document URL, limitations, handoff and maintenance.
12. **Evolution:** use feedback and data to prioritize improvements.

## Principles
- Strategy and aesthetics work together.
- Mobile, accessibility, security and performance are part of quality.
- References transfer principles, not complete layouts or identities.
- Do not invent facts, testimonials, credentials, guarantees or results.
- Do not silently change approved decisions.
- Inspect before editing; report only checks actually performed.

## Reference research
Research on two axes: (1) the client's segment and (2) the specific pattern/experience needed, regardless of segment. Open only relevant reference cards and original sites. Record evidence status and why a pattern transfers. A library entry is not proof that the original site was inspected.

## Motion and interaction
Motion is contextual, not a quota or universal deliverable count. Decide whether it adds value based on brand, content, journey, audience, device, accessibility and performance. A restrained or static experience is valid when intentional. When motion/interactions are used, specify purpose, trigger, states, mobile behavior and acceptance criteria; implement and test actual behavior. Use the Motion System via the task index only when relevant.
